# 论文思维：把概念重新发明一遍

核心：不从定义出发，而是从「当时要解决什么问题」出发，只用当时手头有的东西，一步步把这个概念重新造出来。顺序和一篇论文一样：动机（为什么需要）→ 背景（手头有什么）→ 方法（怎么找到的）→ 理论（为什么一定对）。

教科书的「定义 → 性质 → 例题」是整理之后的顺序，不是东西被想出来的顺序，所以定义常常像凭空出现。论文思维要回答三个问题：
- 为什么要有它
- 怎么想到的
- 为什么能行

讲得好不好，看一点：听完的人会不会觉得「换我站在那个位置，也能一步步走到这里」。目标不是又推导了一遍，而是看着它诞生。

## 什么时候用
- 用户问「为什么要有 X」「X 是怎么想到的」「X 为什么能工作」「这个公式怎么来的」。
- 讲解一个定义或公式看起来像凭空出现的东西：数学公式和定理、物理量、算法、数据结构、编码方式、电路、协议、控制方法。
- 用户说「用论文思维讲」「带我重新发明一遍」。

## 什么时候不用
- 用户只要结论、数值或速查。
- 用户要的是答案或成品（作业、报告正文），不是讲解。
- 内容本身是纯约定（记号怎么写、单位怎么取）。直接说明这是约定，不要硬编一个需求。
- 判断或决策类问题（值不值得、该不该选）。
- 概念太小，四步走完反而啰嗦。这时直接讲，最多加一句它解决了什么问题。

## 步骤

### 1. 提炼需求：为什么要发明它
- 把需求落到一个具体任务上：想做成什么事，没有它会卡在哪里。
- 判断需求属于哪一类，这决定后面往哪个方向找：
  - 某件事根本做不到
  - 做得到，但太贵、太慢、太繁
  - 几种情况各有一套办法，想统一成一套
  - 现有办法有歧义或例外
- 先摆出最朴素的方案，拿去实际用一下，指出它在哪里不够。不够的地方就是下一个需求。需求通常是一条链，不是一个点。
- 用一句话写下最终要找的东西：「我们想要一个……，使得……」，并说清怎样才算解决。

### 2. 盘点资源：手头有什么可以用
- 站在发明者的位置，列出可以直接用的东西：已知的结论、已有的运算或操作、已有的表示方法、能借用的工具。也包括学习者此刻已经掌握的前置知识。
- 评估每样资源的可操作性：做起来容易还是费劲，代价多大，有什么限制。便宜的操作排在前面。
- 写明约束：哪些东西不能用（当时还没有的、代价太高的、学习者还没学到的）。
- 这一步划定了搜索范围：答案只能用清单里的东西搭出来。后面如果要用清单之外的东西，回到这一步补上，并说明它从哪来。

### 3. 发现方法：怎么一步步找到的（核心步骤，篇幅最大）
每一步都要回答「为什么会想到这一步」。理由可以是「这是清单里最简单的操作」「小例子里看到了规律」「目标式子里缺这一项」，但不能没有。

常用的走法：
- 先试最简单的：把资源清单里最便宜的操作逐个试一遍。
- 化归：把新问题改写成已经会做的问题，比如把减法看成加一个负数。
- 观察结构：算几个小例子，把结果写成式子，找规律。
- 分类讨论：把情况拆开，看每种情况各自需要什么，再问能不能合成一套。
- 从目标倒推：把想要的结果写出来，和现在试出来的结果对比，看差什么。
- 修正差距：试出来的结果和目标之间多出一个没规律的量时，把它拆成有结构的几部分，每一部分对应一个清单里的操作，再把这些修正并进定义里。
- 留下走不通的路：简短说明别的路为什么不行。这解释了最终方案为什么长成这样。

如果某一步确实需要灵感，直说这是一步跳跃，并交代什么线索会把人引到那里，不要装作水到渠成。

### 4. 理论推理：为什么一定对
- 把第 3 步找到的方法写成一般形式，证明它对所有情况成立，而不只是对试过的例子成立。
- 点出推导里真正起作用的那个事实。整个方法能成立，往往就靠这一条。
- 检查边界和代价：有没有例外，适用范围到哪里，付出了什么。
- 用一组具体数字从头到尾走一遍，验证结论。
- 最后才命名：这时再给出教科书上的名字和标准定义，并指出每个名字对应前面搭出来的哪一块。名字是贴在已经造好的东西上的标签，不放在开头。

### 收尾
- 用两三句话回顾整条链：需求、资源、关键的那个观察、结论。
- 回头看教科书的定义，说明它的每个部分为什么是这个样子。
- 如果合适，指出这个方案留下的新问题。它往往就是下一个概念的需求。

## 写作要求
- 重建不等于史实。这条发现路径是合乎逻辑的重建，不要说成「历史上某某就是这样想的」，除非确有依据。知道真实历史不一样时，用一句话点明。
- 正确性优先于叙事。每一步数学都要成立；为了故事顺而含糊过去的地方，要把依据补上。
- 不提前使用结论。用户的问题里已经带着名字没关系，但在把它造出来之前，不用它的标准定义和现成性质来解释它自己。
- 一个概念有多种动机时，选和用户当前学习语境最接近的那个，其余的一句带过。
- 篇幅和概念的分量相称。第 3 步最长；简单概念其余几步各一两句就够。
- 用户想自己推的时候，改成引导：每步只给需求和资源，让用户先试，再接着往下走。
- 格式遵循用户已有偏好。用户没说的话，按步骤编号，用文字和公式讲。

## 回答前自查
- 需求是一个具体任务吗？朴素方案和它的不足写出来了吗？
- 第 3、4 步用到的每样东西，都在第 2 步的资源清单里吗？
- 每一步都有「为什么会想到」的理由吗？有没有凭空「注意到」？
- 一般情况证明了吗？还是只验证了几个例子？
- 用具体数字验证过吗？
- 名字是不是最后才出现的？
- 有没有把重建说成史实？

## 常见错误
- 需求太空：「为了方便计算」「为了更好地描述世界」推不出任何具体方案。
- 从帽子里变兔子：关键一步写成「注意到……」「不妨设……」，却不说为什么会想到。
- 偷用后来的东西：用了发明者当时没有、或学习者还没学到的工具。
- 只讲成功路线：不提朴素方案为什么不行，最终方案就显得多此一举。
- 用定义解释定义：一开头就把名字和标准定义搬出来，后面只是在验证它。
- 只验证不证明：举两个例子成立就当作讲完了。
- 编造历史：把重建的思路安到某个人、某个年代头上。

## 完整示例

问题：「为什么要有反码和补码？它们为什么能工作，是怎么想到的？」（以八位二进制为例）

### 1. 需求
- 计算机要表示负数，而手里只有 0 和 1，所以只能拿一位来表示正负。
- 朴素方案：最高位当符号位，0 为正、1 为负，其余七位是绝对值。
- 拿去做运算：5 + (−3) 按这种表示直接相加，是 00000101 + 10000011 = 10001000，读出来是 −8，错了。
- 新需求：减法就是加一个负数。能不能给负数找一种表示，让加法和减法都用同一套加法完成？

### 2. 资源
- 对一串二进制位能做的便宜操作只有两种：加法、按位取反。
- 八位加法只保留低八位，最高位的进位自动丢掉，相当于所有结果都对 256 取余。
- 约束：不想为减法另造一套办法，也不想在运算前先判断符号。

### 3. 发现
- 清单里除了加法就只有取反，所以先试取反：把负数的八位全部取反，看会得到什么。
- 把结果写成式子：−x 在朴素方案里当作无符号数是 128 + x，八位全部取反相当于用 255 去减，得到 127 − x。
- 和目标对比：想要的是 a − x，现在有 a + (127 − x) = (a − x) + 127，多出一个 127。
- 修正差距：127 本身没有规律，拆成 128 − 1，于是 a − x = a + (127 − x) + 1 − 128。
  - 「+1」就是加一，清单里有。
  - 「−128」在对 256 取余的意义下等于「+128」，而加 128 只会把最高位翻一次，也就是把符号位再取反一次。
- 并进定义：符号位取反两次等于没动。所以规定负数的新表示是「符号位不动，其余各位取反，再加一」，这样两个数直接相加就是答案。
- 走不通的路：停在「符号位不动、其余各位取反」而不加一，也能做加法，但每当最高位有进位，要把进位再加回最低位才对，而且 0 会有 00000000 和 11111111 两种写法。加一之后这两个毛病都消失。

### 4. 推理
- 一般形式：对 1 ≤ x ≤ 127，「符号位不动、其余各位取反」的值是 255 − x，再加一是 256 − x。
- 真正起作用的事实：八位加法里 256 等于 0。所以 a + (256 − x) 和 a − x 的低八位完全相同，对所有 a 和 x 都成立。
- 适用范围：真实结果落在 −128 到 127 之间时，读出来的就是正确答案；超出这个范围就是溢出。
- 数字验证：5 − 3 即 00000101 + 11111101 = 1 00000010，丢掉进位得 00000010，等于 2。
- 命名：最初的朴素方案叫原码，「符号位不动、其余各位取反」叫反码，「反码加一」叫负数的补码，正数的补码就是它本身。结论：补码相加即所求。

### 收尾
- 整条链：要表示负数 → 加符号位 → 想让加减法共用一套加法 → 手头只有加法和取反 → 取反后多出 127 → 拆成 128 − 1 → 得到「取反加一」。
- 回头看定义：「取反」来自手头最便宜的操作，「加一」和「符号位不动」来自对 127 的修正，整件事成立靠的是八位加法自动丢进位。
- 史实说明：以上是按逻辑重建的路径。用补数把减法变成加法的做法，早在十进制的机械计算器上就有了。

## 简短示例：公式类

问题：「对数是怎么来的？为什么 log(xy) = log x + log y？」
- 需求：十七世纪初的天文计算里有大量多位数乘除，手算又慢又容易错。需求属于「做得到但太繁」：想把乘法换成更省力的运算。
- 资源：加减法便宜，乘除法贵；已经知道同底数的幂相乘时指数相加，比如 2^3 × 2^5 = 2^8；可以事先编好数表供人查。
- 发现：幂的乘法已经是「指数相加」了，那只要把两个数都写成同一个底数的幂，乘法就变成加法。小例子：算 8 × 32，查到 8 = 2^3、32 = 2^5，指数相加得 8，再查 2^8 = 256。剩下的麻烦是整数指数太稀疏，2 的幂之间隔得很远，中间的数查不到，所以要让表变密：要么选一个很接近 1 的底数，要么允许指数取分数。
- 推理：设 x = a^m，y = a^n，则 xy = a^(m+n)。把「x 是 a 的多少次幂」这个指数记作 log_a x，就得到 log_a(xy) = log_a x + log_a y。
- 命名：这个指数叫对数。
- 史实说明：纳皮尔 1614 年发表对数时，是用两个运动的点来定义的；把对数看成指数是后来才整理出来的讲法。
