# 用第一性原理回答概括性问题

核心：不从"别人怎么说""过去怎么样"出发，而是把问题拆到不能再拆的事实，再只用这些事实重新推出结论。

判断拆得深不深，看四点：
- 每个关键判断是否一路追问到了"地基"，而不是停在常识或别人的观点上
- 是否从多个维度拆，而不是只看一个角度
- 能量化的地方有没有量化
- 结论有没有经过现实校验、极端测试和反方论证

## 什么时候用
- 问题是概括性的、可以拆开的，常见答案大多来自类比、惯例或流行说法。比如：
  - "AI 会写代码了，学计算机还值不值？"
  - "为什么电池/房子/一杯咖啡这么贵？"
  - "该不该转专业 / 创业 / 读研 / 出国？"
  - "某个行业未来几年会怎样？"
  - "怎样学某样东西最快？"
- 用户明确说"用第一性原理想一想""回到本质分析""从头推一遍"。

## 什么时候不用
- 纯事实查询、有标准答案的计算题或作业题。
- 用户只要一个快速结论，或者在倾诉情绪而不是要分析。
- 问题太小，拆了反而啰嗦。这时直接回答，最多加一句关键依据。

## 深度标准：拆到哪里才算够

### 追问链
- 每个关键判断都要写出一条追问链，一般至少三层，直到碰到"地基"。
- 写法：结论 ← 因为 A ← 因为 B ← 地基：C。
- 判断到没到底：对最后一层再问一次"为什么"。
  - 如果回答是"这是物理定律 / 数学定理或定义 / 被大量证据反复验证的规律"，就到底了。
  - 如果回答是"大家都这样""以前一直这样""专家说的""新闻上说的"，就还没到底，继续拆。

### 地基的种类（按硬度从高到低）
- 物理与工程约束：能量守恒、材料性质、信号传播速度、散热、晶体管尺寸极限等。
- 数学与逻辑：定义、定理、不可判定性、组合爆炸、概率规律等。
- 稳健的经济规律：价格由稀缺和边际价值决定、替代品与互补品、规模效应、激励决定行为、机会成本。
- 人的基本动机与认知规律：趋利避害、损失厌恶、注意力有限、社会比较、对确定性的偏好。
- 制度与规则：法律、监管、组织惯例。这是"软地基"，可以改变，必须标注出来。

## 步骤

### 1. 界定问题
- 用一句话重述问题。
- 明确目标：用户真正想优化什么？收入、兴趣、风险、时间、影响力？目标不同，结论可能完全不同。目标不清时，分别给出不同目标下的结论，或者先问一句。
- 明确边界：时间尺度（一年、五年、二十年）、对象（谁、在哪、什么条件）、已知约束。
- 检查问题本身有没有问错：
  - 伪二选一："学不学"其实是"学哪一层"
  - 范畴错误："贵不贵"其实是"贵在哪一环"
  - 预设错误：问题里藏着一个本身不成立的前提
- 如果需要改写问题，说明为什么。

### 2. 常见回答及其来源
- 写出 2～3 种大家常说的答案。
- 每种点明它靠的是什么：历史类比、过去的经验、别人的做法、一句口号、幸存者偏差。
- 这一步要短，作用是让读者看到"不用第一性原理会怎么想"。

### 3. 列出假设清单
- 列出 5～10 条隐含假设，来源包括问题本身和常见回答。
- 每条标注类型：硬事实 / 经验规律 / 习惯或惯例 / 对现状的判断 / 价值偏好。
- 重点找那些"大家默认、但其实不一定成立"的假设。
- 挑出"最关键又最可疑"的 2～3 条，在下一步重点拆。

### 4. 多维拆解（核心步骤，篇幅最大）
至少从下面 3～4 个维度拆，每个维度都要有追问链。某个维度明显无关可以跳过，但要说一句为什么。

- 物理 / 技术维度
  - 它由什么组成？受什么物理或技术约束？
  - 理论极限在哪里？现在离极限还有多远？
  - 哪些约束是硬的（物理），哪些只是当前技术水平造成的？
- 成本 / 经济维度
  - 把成本结构拆到最小单元：材料、人工、能源、资本、设备折旧、协调成本、风险溢价、营销和品牌。
  - 价值在链条的哪一环产生？哪一环最稀缺？
  - 有哪些替代品和互补品？某样东西变便宜后，什么会升值、什么会贬值？
  - 有没有规模效应或网络效应？
- 需求 / 人的维度
  - 谁需要它？为什么愿意付出钱或时间？
  - 需求是刚性的还是可替代的？会随价格变化多大？
  - 涉及哪些人的认知或行为规律？
- 制度 / 博弈维度
  - 谁从现状中获益？各方激励是什么？
  - 哪些规则、监管、行业惯例在起作用？
  - 现状为什么能一直维持下去？
- 时间维度
  - 哪些因素正在快速变化？
  - 哪些因素十年后大概率还不变？结论应该尽量建立在不变的因素上。

要求：
- 事实要具体：给出机制、成本拆分或数量级，不要写"本质是满足需求"这种空话。
- 能量化就量化：费米估算、数量级、成本拆分、比例。
- 估算要写出假设，比如"按每杯用豆 18g、豆价 100～200 元/kg 估算"。
- 需要当前真实数据（价格、市场规模、政策、技术指标）时，先搜索，注明来源；查不到就明确说是估算。
- 算出"理论最优"和"现状"之间的差距。差距本身往往是最有价值的信息。

### 5. 解释差距（现实校验）
- 如果推导显示"本来应该更便宜 / 更可行 / 有机会"，但现实不是这样，必须解释为什么。常见原因：
  - 技术还不成熟，或者工程化成本被低估了
  - 协调成本、交易成本高
  - 监管或准入门槛
  - 需要很大规模才能摊薄成本
  - 激励错位：能改变现状的人没有动力改
  - 隐藏成本或风险
  - 推导里漏掉了某个约束
- 追问一句："如果这么明显，为什么别人没做？"答得出来，推导才可信；答不出来，很可能第 4 步漏了东西，回去补。

### 6. 重建结论
- 只用第 4、5 步得到的事实来推导，每个结论标注依据哪条事实；推不出来的东西不要硬加进结论。
- 尽量从地基出发生成 2～3 个候选答案或方案，再逐一比较，而不是只给一个。
- 推演二阶效应：这件事发生以后，接下来又会发生什么？谁会跟着变？
- 极端测试：把关键变量推到极端（成本降到接近 0、规模扩大 100 倍、时间拉到 10 年后、对手全部跟进），看结论还成不成立。

### 7. 可靠性与反证
- 给每个结论标可靠程度：
  - 高：建立在物理、数学或稳健的经济规律上
  - 中：建立在经验规律上
  - 低：建立在对现状的判断上
- 指出整条推导最薄弱的一环，以及它被推翻后结论会怎么变。
- 构造一个最强的反方论证，认真回应，不要稻草人。
- 写出"出现什么信号，说明我错了"。
- 承认不确定性，但不要因此不给结论。

### 8. 行动含义与收尾
- 落到具体：现在该做什么、不该做什么。
- 给出成本最低的验证办法：用多少时间、多少钱能先试一下。
- 列出需要持续观察的信号，以及在什么情况下应该改主意。
- 用一两句话总结最可靠的结论。
- 如果合适，提议用用户自己的具体情况再拆一遍。

## 写作要求
- 每一步都要真的在推导，不能只是换个说法重复常识。
- 追问链要明确写出来，用"←"或"因为……所以……"连接，让读者能逐层检查。
- 不要把类比包装成第一性原理。"回到本质""底层逻辑"这类词不能代替推导过程。
- 地基事实如果涉及专业知识，必须准确。拆错的"底层事实"比类比更误导人。
- 篇幅：默认中长篇，深度优先，但不灌水。问题小可以合并步骤，但第 3～7 步的实质不能省。
- 格式遵循用户已有偏好（例如分点、不用表格、不配图）。用户没说的话，默认用小标题加分点，按步骤排列。

## 回答前自查
- 每个关键结论都有追问链，并且落到了地基吗？
- 至少从 3 个维度拆过吗？
- 能量化的地方量化了吗？估算的假设写出来了吗？
- 解释了"理论最优"和"现实"之间的差距吗？
- 做过极端测试和反方论证吗？
- 有没有哪条"地基"其实只是惯例、别人的观点或我自己的猜测？
- 最后的结论和行动建议，跟前面的拆解对得上吗？

## 常见错误
- 停在第二层："程序员会被取代，因为 AI 能写代码"，没有继续问"程序员的价值到底来自哪一环"。
- 只拆一个维度：只讲技术，不讲成本、需求和激励，结论往往偏。
- 把判断当事实："AI 永远做不好系统设计"是判断，不是定律，必须标注可靠度。
- 事实太抽象："市场决定一切""本质是满足需求"推不出任何具体结论。
- 纸上推导：算出来"应该很便宜"，却不解释现实为什么不便宜。
- 结论和拆解脱节：最后的建议跟前面的分析没有关系。
- 只找支持自己的证据：没有认真构造反方论证。

## 完整示例

问题："AI 越来越会写代码，现在学计算机还值不值？"

### 1. 界定问题
- 目标：一个本科生选方向，想优化的是未来 5～15 年的职业价值和成长空间。
- 改写："值不值"是伪二选一，真正要问的是"AI 普及以后，计算机里哪些能力会升值，哪些会贬值"。

### 2. 常见回答
- "程序员要被淘汰了"：类比工业革命时被机器取代的纺织工。
- "计算机一直是热门，肯定没问题"：拿过去十年的经验类比未来。

### 3. 假设清单
- 程序员的工作 = 写代码（惯例，可疑）
- AI 写代码的能力会继续变强（对现状的判断，较可信）
- AI 能写代码 = 不再需要人（可疑，关键）
- 软件需求总量基本固定（可疑，关键）
- 学计算机 = 学编程（误解）
- 工资由工作难度决定（错误，工资由稀缺性和产出价值决定）

### 4. 多维拆解
- 经济维度
  - 工资 ← 雇主愿意付的价格 ← 这个人带来的产出价值，以及找到替代者的成本 ← 地基：价格由稀缺性和边际价值决定。
  - 软件的完整链条：理解需求 → 设计 → 编码 → 测试调试 → 部署运维 → 出事负责。编码只是其中一环，维护和调试在实际工程里占了很大比重。
  - 编码变便宜 ← AI 降低了编码的边际成本 → 以前不值得做的软件变得值得做 ← 地基：效率提升常常让总消费上升（杰文斯悖论：蒸汽机提高了用煤效率，煤的总消耗反而上升）→ 软件总量增加 → 对互补环节（定义需求、设计、验证、负责）的需求上升。
- 技术维度
  - AI 擅长写常见代码 ← 它从大量现有代码里学到了模式 ← 地基：统计模型在训练分布内表现好，在分布外、长链条、需要精确正确的任务上更难。（这一条是对当前技术的判断，可靠度中）
  - 代码对不对必须验证 ← 验证需要理解规格和整个系统 ← 地基：Rice 定理表明，程序的非平凡语义性质在一般情况下不可判定，所以不存在能自动验证任意程序的通用方法。验证始终有成本。
- 物理维度
  - AI 要运行 ← 需要算力 ← 需要芯片、电力、散热、带宽 ← 地基：计算需要消耗能量，晶体管微缩逼近物理极限，搬运数据的能耗常常比计算本身更高。
  - → 让 AI 跑得更快更省（编译器、并行调度、量化、存储与通信优化、分布式系统）是长期需求，而且 AI 用得越多，这类需求越大。
- 人 / 制度维度
  - 系统出了事故要有人负责 ← 法律和组织需要可问责的主体 ← 地基：责任要落在自然人或法人身上（制度，软地基，可能改变）。
  - 客户经常说不清自己要什么 ← 需求本身是模糊的 ← 地基：人很难提前完整描述自己的需求 → "把模糊需求变成清楚问题"的能力是稀缺的。
- 时间维度
  - 大概率不变：计算受物理约束；价值来自解决问题；稀缺决定价格。
  - 快速变化：AI 能写多复杂的代码；哪些具体岗位存在；流行的框架和工具。

### 5. 解释差距
- 疑问：如果编码变便宜会让软件需求增加，那为什么新手程序员可能反而更难找工作？
- 可能的解释：企业短期内先用 AI 削减重复性岗位，而需求扩张有滞后；入门岗位恰好集中在最容易被替代的那一层；经济周期也有影响。
- 这和推导是一致的：被压缩的是入门编码这一层，而不是整个领域。同时提醒，短期阵痛是真实存在的。

### 6. 重建结论
- 候选方案：
  - A：不学计算机，转别的方向
  - B：学计算机，走应用开发
  - C：学计算机，深入系统和底层（体系结构、操作系统、编译、分布式、AI 基础设施）
  - D：计算机加某个领域知识，做交叉方向
- 比较：
  - B 最依赖"把需求翻译成代码"这一层，受 AI 冲击最大。
  - C 直接对应物理约束和验证成本这两条硬地基，需求会随 AI 普及而上升。
  - D 利用了"需求模糊、领域知识稀缺"这条地基，AI 很难替代对具体行业的理解。
  - A 放弃了一个需求总量在扩大的领域，除非用户的目标根本不在这里。
- 二阶效应：软件变多 → 系统更复杂、漏洞更多 → 安全、可靠性、测试方向的需求上升。
- 极端测试：
  - 如果 AI 编码成本接近 0：B 的价值接近 0，C 和 D 依然成立。
  - 如果 AI 连系统设计也能做好：剩下最稳的是定义问题、承担责任，以及 AI 本身的基础设施。

### 7. 可靠性与反证
- 高可靠：稀缺决定价格；计算的物理约束；程序验证的不可判定性。
- 中可靠：杰文斯效应会不会在软件上明显出现。
- 低可靠：AI 能力多久达到能端到端完成大型系统；"人类在上层设计上会一直占优"。
- 最强反方：如果 5 年内 AI 能独立完成大型系统的设计、实现和验证，连 C 也会被压缩。
- 回应：即便如此，AI 基础设施本身是需求来源；扎实的底层理解也让人能迁移到任何新的层次。
- 我错了的信号：AI 在大型真实代码库上的自主完成率快速上升，同时高级系统岗位的需求也在下降。

### 8. 行动含义
- 学习上，原理优先于框架：体系结构、操作系统、网络、编译原理、算法。
- 每学一门课，配一个能碰到底层的小项目，比如自己写一个简单的内存分配器或推理加速实验。
- 日常可以用 AI 写代码，但坚持读懂、写测试，练习发现 AI 代码的错误。
- 做至少一个"计算机加领域知识"的交叉项目。
- 每半年看一次上面列出的信号，重新评估方向。

## 简短示例：成本类问题

问题："为什么咖啡店一杯拿铁要卖 30 元？"
- 原料估算（假设，需要时搜索当前价格）：咖啡豆每杯约 18g，按 100～200 元/kg 约 2～4 元；牛奶约 200ml，约 3 元；杯子、杯盖、吸管约 1 元。原料合计约 6～8 元。
- 剩下的钱去哪了：房租（与位置和面积有关）、店员人工、设备折旧、水电、损耗、品牌和营销、利润。
- 追问链：售价远高于原料 ← 顾客买的不只是咖啡，还有位置、时间、空间和品牌 ← 地基：人愿意为便利、确定性和社交意义付费。
- 解释差距：为什么有的连锁品牌能卖到十几元？← 小面积外卖店降低房租、规模采购降低原料成本、数字化点单减少人工 ← 地基：规模效应和固定成本摊薄。
- 结论：拿铁贵主要贵在"空间和时间"，不在"咖啡"本身。想便宜就去掉不需要的部分，比如外带或者自己做。
